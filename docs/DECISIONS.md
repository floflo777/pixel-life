# Decisions (canonical)

When design documents disagree, this file wins; after it, **the code in `packages/shared` wins** over any prose.
Order of authority for everything else: `docs/design/tokenomics/tokenomics.md` for economy numbers,
`docs/design/architecture.md` (its final HOSTING DECISION section overrides §4) for technology,
`docs/design/art/art-bible.md` for visuals, `docs/design/gdd.md` for gameplay feel.

| #    | Topic               | Decision                                                                                                                                                                                                                                         |
| ---- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| D-01 | Backend             | Node 22 + Fastify + `ws` + PostgreSQL 16 on the owner's server (`apps/server`), public entry = Cloudflare edge Worker (`workers/edge`) on `*.workers.dev`. No D1 / Durable Objects.                                                              |
| D-02 | Tooling             | npm workspaces, ESLint + Prettier, Vitest, Playwright. (Architecture §2 mentions pnpm/biome: ignore.)                                                                                                                                            |
| D-03 | Scar model          | A `Hex64` lost mask over `frontMask()` (idle-down frame 0; Colossus: idle-right frame 0). Stitches and gold are derived layers (`adornment.ts`), not stored per pixel.                                                                           |
| D-04 | Free regrowth       | 0.5 px/h, +25 % per Gold Pixel held, max 2 (tokenomics). Healing order = per-token seeded permutation (`regrowthOrder`), not oldest-first.                                                                                                       |
| D-05 | Prices              | Regrow 0.5 RF/px (50 % burn / 50 % protocol stream via `ActivationManager.fund`), Mend 1.0 RF/px (50 % burn / 50 % to the target Friend's wallet), Seed Pack 5 RF (`docs/design/tokenomics/game.json`). Source of truth: `ECON` in `@pl/shared`. |
| D-06 | Soft currency       | Named **Bits** (not "Crumbs"). Rules as data in `BITS` (`@pl/shared`). Never converts to RF.                                                                                                                                                     |
| D-07 | Scars per run       | `runScarCap(n0) = min(12, max(6, round(0.15·n0)))`; persisted loss floor 50 % (`maxPersistedLost`).                                                                                                                                              |
| D-08 | Venue contract      | Architecture §1b.2 as implemented in `@pl/venue-kit` (GDD §11.7 interfaces are superseded).                                                                                                                                                      |
| D-09 | Hub rooms & density | Rooms: `plaza`, `pixel-arena`, `seed-booth`, `sky-docks`, `daily-gate`. Soft cap 40, hard cap 60 per shard. Movement is event-driven click-to-move (no 10 Hz stream).                                                                            |
| D-10 | Mend                | Target must currently have lost pixels; cannot mend your own Friend with the same Friend (`self_mend`); cap 24 px/day per payer; stitches visible 7 days.                                                                                        |
| D-11 | Guest mode          | Guests never enter the FriendSDK gated runtime; loaned Friends are baked at build time; guest scars live in localStorage only. Stated plainly in the submission README.                                                                          |
| D-12 | Real RF             | Default `ECONOMY_MODE=sim`, labelled SIMULATED everywhere. Live mode = contracts in `contracts/` (not deployed, not audited) + owner authorization.                                                                                              |
| D-13 | Gold in play        | A Gold Pixel never gives in-run power; perks are read live from held kept rewards, so redeeming removes them (no double spend).                                                                                                                  |
| D-14 | Name | Product and flagship venue: **Loose Pixels**. Hub: **The Sky**. Internal package scope stays `@pl/*`. Public URL `loose-pixels.<sub>.workers.dev`. |
| D-15 | Guest-mode commitment | The judges' FAQ keeps the promise to disable guest mode if the organizers consider it outside the FriendSDK rules. |
